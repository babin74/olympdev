## Solution tag logic

Уникальность тегов уже проверяется при загрузке задачи
(`ProblemConfiguration._check_solution_tags`): "main" ровно один, остальные теги
не повторяются; есть тесты в `tests/test_problem_package.py`.

Осталось:

- [ ] Снять жёсткий список значений в `ProblemSolution._check_tag`
      (сейчас только main/OK/WA/TL/ML) — разрешить произвольные теги вроде
      "pretests", "alt".
- [ ] Согласовать с этим `get_permissible_verdicts` / `get_expected_verdicts`:
      они разбирают теги по строкам и после снятия списка потеряют смысл.
- [ ] Описать допустимые теги в README.

**Пример поведения:**

- Если есть несколько решений с тегом "main" — должна быть ошибка.
- Если у двух решений один и тот же кастомный тег (например, "wa") — должна быть ошибка.
- Если есть "main", "wa", "tl", "alt" и все уникальны — валидно.

## Subtasks

- [ ] В перспективе предусмотреть возможность работы с подзадачами (subtasks), аналогично формату IOI-задач:
  - Каждый тест может относиться к одной или нескольким подзадачам.
  - Оценивание результатов должно учитывать структуру подзадач, например, начислять баллы только за полностью решённую подзадачу.
  - Интерфейс и структура описания задачи должны поддерживать информацию о подзадачах (название, вес, состав входящих тестов).
  - Учесть особенности обработки вердиктов и начисления баллов для подзадач.
  - Добавить тесты на корректную работу с подзадачами и описание необходимых изменений в формате задачи.
